# MongoDB — introdução e operações básicas

## 1. MongoDB e bancos relacionais

O MongoDB é um banco NoSQL **orientado a documentos**. Em vez de tabelas com linhas e colunas, organiza **documentos** em **coleções**. Cada documento reúne campos e valores; documentos da mesma coleção podem ter campos diferentes. Essa flexibilidade ajuda quando a estrutura dos dados evolui, mas ainda exige uma modelagem cuidadosa.

| Banco relacional | MongoDB |
| --- | --- |
| Tabela | Coleção |
| Linha | Documento |
| Coluna | Campo |
| Chave primária | Campo `_id`, único na coleção |

Os documentos são armazenados em **BSON**, representação binária semelhante a JSON que admite tipos adicionais, como datas e `ObjectId`. No `mongosh`, escrevemos objetos com sintaxe de JavaScript. O campo `id` é apenas um campo comum; se `_id` não for informado, o MongoDB gera um identificador para o documento.

```javascript
{
  _id: 8,
  nome: "Cliente Exemplo",
  telefones: ["(16) 99999-0000", "(16) 3333-0000"],
  endereco: { cidade: "São Carlos", uf: "SP" },
  ativo: true
}
```

Nesse exemplo, `telefones` é um **array** e `endereco` é um **documento aninhado**. O modelo admite também números, valores booleanos, `null` e datas. Para armazenar uma data de verdade, use um valor como `ISODate("2024-11-05")` no `mongosh`, em vez de uma string formatada como `"05/11/2024"`.

### Por que usar?

- **Esquema flexível:** documentos de uma coleção podem variar conforme os dados disponíveis.
- **Escala horizontal:** *sharding* distribui dados entre servidores; requer configuração própria.
- **Disponibilidade:** conjuntos de réplicas mantêm cópias dos dados em outros servidores.
- **Consultas:** índices e agregações ajudam em buscas e análises, conforme o caso.

Os slides citam aplicações web, e-commerce, logs, sensores e geolocalização como exemplos. Flexibilidade não significa que MongoDB será sempre mais rápido ou adequado: a escolha depende das consultas, da consistência necessária e da forma de acesso aos dados.

## 2. Ambiente e primeiros comandos

Na aula são usados o **MongoDB Server**, o **MongoDB Compass** (interface gráfica) e o **MongoDB Shell**, chamado `mongosh`. Com o servidor em execução e o shell instalado, uma conexão local pode ser iniciada assim:

```text
mongosh
```

No `mongosh`:

```javascript
show dbs                 // lista bancos que já têm dados
use aula                 // seleciona o banco; ainda não grava nada
db.createCollection("clientes")
show collections
```

`use aula` sozinho não torna o banco visível em `show dbs`: é preciso criar uma coleção e/ou gravar dados. `admin`, `config` e `local` são bancos usados pelo próprio MongoDB. O `Compass` permite criar bancos e coleções, editar documentos e executar filtros pela interface.

## 3. Inserir e consultar documentos

`insertOne()` insere um documento. `insertMany()` recebe um **array** de documentos. Os exemplos abaixo usam `_id` explícito para facilitar as consultas seguintes; se executar novamente os mesmos inserts, haverá erro de chave duplicada.

```javascript
use aula

db.clientes.insertOne({
  _id: 8,
  nome: "Cliente Exemplo",
  email: "cliente@example.com",
  telefones: { Celular: { ddd: 16, numero: "99999-0000" } },
  enderecos: { casa: { cidade: "São Carlos", uf: "SP" } },
  metodos: { metodo1: { tipo: "Cartão", validade: "12/24" } },
  pedidos: []
})

db.clientes.insertMany([
  { _id: 11, nome: "Cliente Onze" },
  { _id: 12, nome: "Cliente Doze", ativo: true }
])
```

`findOne()` retorna um documento correspondente ou `null`. `find()` retorna um cursor com os documentos encontrados. Um filtro `{}` não restringe a busca.

```javascript
db.clientes.findOne({ _id: 8 })
db.clientes.find({})
db.clientes.find({ ativo: true })
```

> [!important] `_id` x `id`
> O slide compara os dois campos: `{ id: 1 }` não define o identificador do MongoDB. Só `_id` tem esse papel e a garantia de unicidade dentro da coleção.

## 4. Atualizar documentos

`updateOne(filtro, alteração)` modifica o primeiro documento encontrado; `updateMany()` modifica todos os que satisfazem o filtro. O segundo argumento normalmente usa operadores de atualização:

| Operador | Efeito |
| --- | --- |
| `$set` | Cria ou substitui o valor de um campo |
| `$unset` | Remove um campo |
| `$push` | Adiciona um elemento a um array |
| `$pull` | Remove do array os elementos que correspondem ao valor ou critério |

```javascript
db.clientes.updateOne(
  { _id: 8 },
  { $set: { email: "novo@example.com", "enderecos.casa.cep": "13560-000" } }
)

db.clientes.updateOne({ _id: 8 }, { $unset: { email: "" } })
db.clientes.updateOne({ _id: 8 }, { $push: { pedidos: 15 } })
db.clientes.updateOne({ _id: 8 }, { $pull: { pedidos: 15 } })
```

A **notação de ponto** alcança campos dentro de documentos, como `enderecos.casa.cep`. Se `$set` receber `enderecos` em vez do caminho completo, substituirá o objeto inteiro e poderá apagar outros endereços.

Para mudar todos os documentos da coleção:

```javascript
db.clientes.updateMany({}, { $set: { status: "ativo" } })
```

Use um filtro específico quando a alteração não deve atingir toda a coleção.

## 5. Modelar clientes e pedidos

A aula compara duas escolhas para um sistema de clientes e pedidos:

1. **Pedidos incorporados ao cliente:** a coleção `clientes` contém um array `pedidos`, e cada pedido pode conter itens, endereço de entrega e forma de pagamento. É conveniente quando a leitura costuma trazer cliente e pedidos juntos. O documento pode crescer bastante, e atualizar um pedido exige acessar o array interno.
2. **Coleções separadas:** `clientes` guarda os dados do cliente, e `pedidos` guarda cada pedido com `id_cliente`. É mais natural quando pedidos são consultados e atualizados separadamente. Os itens e os dados de entrega ainda podem ficar incorporados em cada pedido.

Exemplo da segunda escolha:

```javascript
db.pedidos.insertOne({
  _id: 15,
  id_cliente: 8,
  data: ISODate("2024-11-05"),
  status: "Aprovado",
  itens: [{ codigo: 101, descricao: "Livro", preco: 45, qtde: 1 }],
  endereco_entrega: { cidade: "São Carlos", uf: "SP" }
})

db.pedidos.find({ id_cliente: 8 })
```

A aula mostra a possibilidade de guardar também os IDs dos pedidos no cliente. Isso cria **referência dupla**: ao inserir ou remover um pedido, as duas coleções precisam ser mantidas em sincronia. Se a consulta por pedidos de um cliente via `id_cliente` atende ao caso, guardar essa referência só em `pedidos` evita a duplicação.

Na modelagem com pedidos incorporados, `$push` adiciona um pedido ao array. O operador posicional `$` indica o primeiro elemento do array que correspondeu ao filtro:

```javascript
db.clientes.updateOne(
  { _id: 7, "pedidos.numero": 189 },
  { $push: { "pedidos.$.itens": { codigo: 101, descricao: "Livro", qtde: 1 } } }
)
```

Esse último comando é **um exemplo da outra modelagem**: pressupõe um cliente de `_id: 7` com `pedidos` incorporados e um pedido de número `189`. Ele não altera os documentos de `clientes` e `pedidos` separados criados acima.

## 6. Remover dados

```javascript
db.pedidos.deleteOne({ _id: 15 })
db.pedidos.deleteMany({ id_cliente: 8 })
```

`deleteOne()` remove no máximo um documento; `deleteMany()` remove todos os que correspondem ao filtro. `deleteMany({})` remove **todos os documentos** da coleção. Para remover a coleção inteira, use `db.pedidos.drop()`; para remover o banco selecionado, `db.dropDatabase()`. Confira o banco atual antes de usar esses comandos.

## 7. Filtros, projeção e ordenação

Em filtros, operadores de comparação começam com `$`: `$gt` (maior), `$gte` (maior ou igual), `$lt` (menor), `$lte` (menor ou igual), `$ne` (diferente) e `$in` (pertence à lista). `$all` exige que um array contenha **todos** os valores informados.

```javascript
db.pedidos.find({ _id: { $in: [11, 15] } })
db.pedidos.find({ data: { $gte: ISODate("2024-01-01") } })
db.pedidos.find({ "itens.qtde": { $gte: 1 } })
db.clientes.find({ pedidos: { $all: [11, 15] } })
```

O primeiro argumento de `find()` é o **filtro**; o segundo é a **projeção** dos campos retornados. `1` inclui, `0` exclui. `_id` aparece por padrão e pode ser excluído mesmo ao incluir outros campos. Em geral, não misture inclusão e exclusão de campos na mesma projeção, com essa exceção de `_id`.

```javascript
db.pedidos.find(
  { "itens.qtde": { $gte: 1 } },
  { id_cliente: 1, status: 1, _id: 0 }
).sort({ data: -1 }).limit(10)
```

Em `sort()`, `1` ordena em ordem crescente e `-1` em decrescente. `skip()` ignora uma quantidade de documentos; `limit()` limita o total retornado. No Compass, os campos **Filter**, **Project**, **Sort**, **Skip** e **Limit** fazem esse papel. A aula também apresenta **Collation** (regras de comparação de texto), **Max Time MS** (limite de tempo) e **Index Hint** (índice indicado para a consulta). Para importar ou exportar dados no Compass, há opções para JSON e CSV.

> [!note] Datas no Compass
> No `mongosh`, `ISODate("2024-11-05")` cria uma data BSON. Ao editar em JSON estendido no Compass, uma representação possível é `{ "$date": "2024-11-05T00:00:00Z" }`. Uma string com a data não recebe automaticamente o mesmo tipo.

## 8. Exercícios finais da aula

Os exercícios usam os documentos de `clientes` e `pedidos` da **modelagem em duas coleções** apresentada nos slides. Os comandos abaixo seguem o **enunciado**; o gabarito do exercício 2 usa `_id: 24`, embora o pedido solicitado seja o de `_id: 15`.

```javascript
// 1. Mostrar o pedido 15.
db.pedidos.findOne({ _id: 15 })

// 2. Registrar cancelamento e mudar o status do pedido 15.
db.pedidos.updateOne(
  { _id: 15 },
  { $set: { data_cancelamento: ISODate("2024-11-05"), status: "Cancelado" } }
)

// 3. Adicionar e-mail ao cliente 8.
db.clientes.updateOne(
  { _id: 8 },
  { $set: { email: "cliente8@example.com" } }
)

// 4. Adicionar telefone do tipo Casa ao cliente 8.
db.clientes.updateOne(
  { _id: 8 },
  { $set: { "telefones.Casa": { ddd: 16, numero: "3422-9876" } } }
)

// 5. Adicionar endereço de trabalho ao cliente 8.
db.clientes.updateOne(
  { _id: 8 },
  { $set: { "enderecos.trabalho": { cidade: "Ribeirão Preto", uf: "SP" } } }
)

// 6. Alterar a validade do primeiro método de pagamento do cliente 8.
db.clientes.updateOne(
  { _id: 8 },
  { $set: { "metodos.metodo1.validade": "12/25" } }
)
```

> [!warning] Ao praticar os comandos
> Os exemplos de remoção da seção 6 apagam documentos. Para executar os exercícios depois deles, reinsira os documentos necessários. Os exemplos de modelagem incorporada e de coleções separadas representam estruturas alternativas; use os comandos correspondentes à estrutura que você criou.
