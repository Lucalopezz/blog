# 3.Exercicios-Mongo

## Antes de começar: importar os dados no MongoDB em Docker

Os dois arquivos fornecidos representam **os mesmos oito clientes**, com pedidos incorporados, mas não têm valores totalmente iguais. Importe **apenas um deles** para não duplicar os `_id`. Para este roteiro, use `clientes_pedidos.json`: ele contém oito documentos JSON consecutivos e usa `{"$date": "..."}` para datas. O arquivo `clientes_pedidos_array.json` já tem colchetes, mas usa `{"ISODate": "..."}` em algumas datas; isso **não é** a representação Extended JSON de uma data BSON.

No terminal do computador que executa o Docker:

```bash
# 1. Descubra o nome do contêiner MongoDB em execução.
docker ps --format 'table {{.Names}}\t{{.Image}}\t{{.Ports}}'

# 2. Troque meu-mongo pelo nome encontrado. O jq roda no computador;
#    o mongoimport roda dentro do contêiner.
MONGO_CONTAINER=meu-mongo
cd ~/Downloads
jq -s '.' clientes_pedidos.json |
  docker exec -i "$MONGO_CONTAINER" mongoimport \
    --db banco2_exercicios \
    --collection clientesPedidos \
    --jsonArray \
    --stopOnError

# 3. Confira a importação no mongosh dentro do contêiner.
docker exec -it "$MONGO_CONTAINER" mongosh banco2_exercicios
```

Já no prompt do `mongosh`:

```javascript
db.clientesPedidos.countDocuments({}) // esperado: 8
db.clientesPedidos.findOne({ _id: 1 }, { nome: 1, "pedidos.numero": 1 })
```

O `jq -s` transforma os oito objetos consecutivos em **um array JSON**; por isso o `mongoimport` recebe `--jsonArray`. Se `jq` não estiver instalado no seu computador, instale-o ou gere esse array com outra ferramenta. Se `mongoimport` não existir dentro do contêiner, instale as **MongoDB Database Tools** no computador e conecte-se pela porta publicada do Docker; `mongosh` é instalado separadamente como **MongoDB Shell**. O comando mostrado pressupõe conexão local **sem autenticação**; se a sua instância exige usuário, use as credenciais e o banco de autenticação configurados no seu contêiner. Execute a importação uma vez: repetir na mesma coleção causa erro de `_id` duplicado.

> [!warning] Diferença entre os arquivos
> No cliente `_id: 3`, o pedido `155` tem `total: 434.0` em `clientes_pedidos.json` e `total: 330.8` em `clientes_pedidos_array.json`. Os resultados esperados do bloco **C** consideram **o primeiro arquivo**, importado pelo comando acima. Os itens desse pedido somam `434.0` (387,50 + 3 × 15,50).

> [!important] Três conjuntos de dados diferentes
> **A** usa `bandas`, `locais` e `shows`, como no guia de consultas; os JSONs fornecidos **não** criam essas coleções. **B** usa `clientes` e `pedidos` em coleções separadas, como nos slides de MongoDB; os JSONs também **não** criam esse modelo. **C** usa `clientesPedidos`, a coleção importada acima. Escolha o conjunto correto antes de executar cada solução.

Nos exemplos de **A**, `bandas._id` é o nome da banda; `shows._id` contém `banda`, `local` e `data`, e essa `data` é uma **string** no formato `AAAA-MM-DD`. As informações de cidade e estado do show ficam em `detalhes_local`. Nos exemplos de **B**, existem o cliente `_id: 8` e o pedido `_id: 15` em coleções distintas. Em **C**, cada cliente tem um array `pedidos`; nem todos os documentos têm os mesmos formatos de telefone, endereço e pagamento.

# Resoluções

## A. Gabarito dos exercícios da aula: bandas, locais e shows

As respostas são **consultas**, não resultados calculados: os slides mostram a estrutura de exemplo, mas não fornecem uma coleção completa de bandas, locais e shows para executar todas elas. `find()` retorna um cursor; `findOne()` retorna um documento ou `null`.

### A1 a A6 — consultas básicas, projeção e arrays

```javascript
// A1. Todas as bandas.
db.bandas.find({})

// A2. O nome da banda é o campo _id no modelo da aula.
db.bandas.find({}, { _id: 1 })

// A3. Uma banda específica.
db.bandas.findOne({ _id: "U2" })

// A4. Após 1990: 1990 não entra no resultado.
db.bandas.find(
  { ano_criacao: { $gt: 1990 } },
  { _id: 1, ano_criacao: 1 }
)

// A5. Desdobra os integrantes para selecionar exatamente Mick Jagger.
db.bandas.aggregate([
  { $unwind: "$integrantes" },
  { $match: { "integrantes.nome": "Mick Jagger" } },
  { $project: { _id: 0, banda: "$_id", instrumentos: "$integrantes.instrumentos" } }
])

// A6. Capacidade estritamente superior a 60.000.
db.locais.find({ capacidade_publico: { $gt: 60000 } })
```

### A7 a A13 — shows e locais

**A7.** O modelo de `locais` da aula **não possui disponibilidade** nem uma data para verificar agenda. É possível filtrar os locais de São Paulo, mas não afirmar quais estão livres:

```javascript
db.locais.find({ cidade: "São Paulo" })
```

Para responder “disponíveis”, seria preciso definir **em qual data** e comparar a agenda de shows, ou armazenar uma disponibilidade com significado claro.

```javascript
// A8. Local e data dos shows do Coldplay.
db.shows.aggregate([
  { $match: { "_id.banda": "Coldplay" } },
  { $project: { _id: 0, local: "$_id.local", data: "$_id.data" } }
])

// A9. Banda e data dos shows no Allianz Parque.
db.shows.aggregate([
  { $match: { "_id.local": "Allianz Parque" } },
  { $project: { _id: 0, banda: "$_id.banda", data: "$_id.data" } }
])

// A10. A data foi armazenada como string AAAA-MM-DD no modelo da aula.
db.shows.find({ "_id.data": "2024-12-07" })

// A11. Exemplo de cidade específica: São Paulo.
db.shows.find({ "detalhes_local.cidade": "São Paulo" })

// A12. Abaixo de R$ 500; ingressos de R$ 500 não entram.
db.shows.find({ valor_ingresso: { $lt: 500 } })

// A13. Bandas distintas com show no Morumbi.
db.shows.distinct("_id.banda", { "_id.local": "Morumbi" })
```

Em **A8** e **A9**, `$project` cria nomes de saída (`local`, `data`, `banda`) a partir dos subcampos de `_id`. Se preferir uma consulta simples, use `find()` sem projeção e leia os subcampos no resultado.

### A14 a A20 — datas, contagem e extremos

```javascript
// A14. Intervalo de strings ISO: inclui todo o ano de 2024.
db.shows.find({ "_id.data": { $gte: "2024-01-01", $lt: "2025-01-01" } })

// A15. Mesmo intervalo, só para Coldplay.
db.shows.find({
  "_id.banda": "Coldplay",
  "_id.data": { $gte: "2024-01-01", $lt: "2025-01-01" }
})

// A16. Exemplo de local específico: Maracanã.
db.shows.countDocuments({ "_id.local": "Maracanã" })

// A17. Estado do local, copiado para o documento do show.
db.shows.find({ "detalhes_local.estado": "SP" })
```

**A18.** `total_ingressos` informa quantos ingressos foram **disponibilizados**, mas o documento não registra quantos foram **vendidos**. É possível consultar a oferta inicial do Iron Maiden:

```javascript
db.shows.find(
  { "_id.banda": "Iron Maiden" },
  { _id: 1, total_ingressos: 1 }
)
```

Para obter os **ainda disponíveis**, seria necessário também um campo de vendas ou reservas. Se fosse criado `ingressos_vendidos`, a conta por show seria `total_ingressos - ingressos_vendidos`.

```javascript
// A19. Menor ano de criação entre as bandas.
db.bandas.find({}, { _id: 0, ano_criacao: 1 })
  .sort({ ano_criacao: 1 }).limit(1)

// A20. Local de maior capacidade.
db.locais.find({}).sort({ capacidade_publico: -1 }).limit(1)
```

### A21 a A28 — agregações

```javascript
// A21. Capacidade média dos locais.
db.locais.aggregate([
  { $group: { _id: null, capacidadeMedia: { $avg: "$capacidade_publico" } } }
])

// A22. Total de ingressos colocados à disposição.
db.shows.aggregate([
  { $group: { _id: null, totalIngressos: { $sum: "$total_ingressos" } } }
])

// A23. Receita hipotética se todos os ingressos forem vendidos.
db.shows.aggregate([
  { $group: {
    _id: null,
    arrecadacao: { $sum: { $multiply: ["$valor_ingresso", "$total_ingressos"] } }
  } }
])

// A24. Quantos shows cada banda realizou.
db.shows.aggregate([
  { $group: { _id: "$_id.banda", totalShows: { $sum: 1 } } },
  { $sort: { _id: 1 } }
])

// A25. Quantos shows ocorreram em cada local.
db.shows.aggregate([
  { $group: { _id: "$_id.local", totalShows: { $sum: 1 } } },
  { $sort: { _id: 1 } }
])

// A26. Média simples do preço do ingresso por show.
db.shows.aggregate([
  { $group: { _id: null, precoMedio: { $avg: "$valor_ingresso" } } }
])
```

**A27.** A quantidade **ainda disponível** não pode ser calculada sem vendas ou reservas. Se “disponíveis” significar **ingressos inicialmente disponibilizados**, a consulta é:

```javascript
db.shows.find({}).sort({ total_ingressos: -1 }).limit(1)
```

Se houver o campo `ingressos_vendidos`, calcule a diferença antes de ordenar:

```javascript
db.shows.aggregate([
  { $project: {
    restantes: { $subtract: ["$total_ingressos", "$ingressos_vendidos"] }
  } },
  { $sort: { restantes: -1 } },
  { $limit: 1 }
])
```

```javascript
// A28. Aluguel médio dos locais.
db.locais.aggregate([
  { $group: { _id: null, aluguelMedio: { $avg: "$valor_aluguel" } } }
])
```

> [!note] Limites dos dados
> **A7, A18 e A27** não têm resposta exata para disponibilidade no esquema apresentado. **A23** é uma simulação expressamente pedida no enunciado. **A26** dá o mesmo peso a cada show; não é o preço médio ponderado pelo número de ingressos.

## B. Gabarito dos exercícios da aula: clientes e pedidos separados

Execute estes comandos **somente** se você tiver criado as coleções separadas `clientes` e `pedidos` usadas nos slides. O arquivo importado no início criou `clientesPedidos`, com pedidos incorporados, e portanto **não fornece** o pedido de `_id: 15` em `db.pedidos`.

```javascript
// B1. Todos os dados do pedido 15.
db.pedidos.findOne({ _id: 15 })

// B2. Um único update para as duas alterações solicitadas.
db.pedidos.updateOne(
  { _id: 15 },
  { $set: { data_cancelamento: ISODate("2024-11-05"), status: "Cancelado" } }
)

// B3. O campo "e-mail" segue o nome usado nos slides.
db.clientes.updateOne(
  { _id: 8 },
  { $set: { "e-mail": "cliente8@example.com" } }
)

// B4. Notação de ponto: adiciona Casa sem substituir os demais telefones.
db.clientes.updateOne(
  { _id: 8 },
  { $set: { "telefones.Casa": { ddd: 16, numero: "3422-9876" } } }
)

// B5. Adiciona um endereço de trabalho.
db.clientes.updateOne(
  { _id: 8 },
  { $set: { "enderecos.trabalho": {
    rua: "R. José Manoel, 54",
    bairro: "Vila Sesamo",
    cidade: "Ribeirão Preto"
  } } }
)

// B6. Altera apenas a validade de metodo1.
db.clientes.updateOne(
  { _id: 8 },
  { $set: { "metodos.metodo1.validade": "12/25" } }
)
```

Se `matchedCount` for `0`, confira se os documentos `_id: 8` e `_id: 15` foram criados **nas coleções e no banco corretos**. O uso de `updateOne()` mantém o filtro por `_id` explícito e evita modificar outro documento.

## C. Gabarito dos exercícios criados para estudo

### C1 a C4 — conceitos

**C1.** (a) **Chave-valor** para recuperar um valor por sua chave; (b) **documentos** para reunir dados de cliente com estrutura variável; (c) **grafos** quando percorrer relações entre pessoas é central. São escolhas ligadas ao padrão de acesso, não apenas ao formato aparente dos dados.

**C2.** Uma **coleção separada de pedidos** tende a ser melhor nesse cenário. Cada pedido pode ser consultado e atualizado sem reescrever um documento de cliente que cresce continuamente. Incorporar pode ser útil quando os pedidos são poucos e quase sempre lidos com o cliente, mas não é a hipótese do enunciado.

**C3.** **Fragmentação** distribui partes diferentes dos dados por nós para dividir armazenamento e carga. **Replicação** mantém cópias dos mesmos dados em nós distintos, ajudando disponibilidade e, conforme a configuração, leitura. As duas estratégias podem ser combinadas.

**C4.** `{"ISODate": "..."}` é um objeto JSON com chave `ISODate`, não o marcador padrão de data no Extended JSON. O outro arquivo usa `{"$date": "2023-05-20T00:00:00Z"}`, que permite importar essa informação como data BSON. O passo com `jq -s` apenas envolve os oito documentos em um array; não altera o marcador `$date`.

### C5 a C12 — dados de `clientesPedidos`

```javascript
// C5. Quantidade de clientes.
db.clientesPedidos.countDocuments({})
// Esperado nos dados fornecidos: 8.

// C6. Array de pedidos vazio.
db.clientesPedidos.find(
  { pedidos: { $size: 0 } },
  { _id: 1, nome: 1 }
).sort({ _id: 1 })
// Esperado: _id 2, 4, 5, 6 e 8.

// C7. Uma linha por pedido incorporado.
db.clientesPedidos.aggregate([
  { $unwind: "$pedidos" },
  { $project: {
    _id: 0,
    idCliente: "$_id",
    numero: "$pedidos.numero",
    total: "$pedidos.total"
  } },
  { $sort: { idCliente: 1 } }
])
// Esperado: pedidos 101, 155 e 113, dos clientes 1, 3 e 7.

// C8. Pelo menos um pedido com entrega em Campinas.
db.clientesPedidos.find(
  { "pedidos.endereco_entrega.cidade": "Campinas" },
  { _id: 1, nome: 1 }
).sort({ _id: 1 })
// Esperado: clientes 1 e 7.

// C9. Estatísticas dos totais dos pedidos.
db.clientesPedidos.aggregate([
  { $unwind: "$pedidos" },
  { $group: {
    _id: null,
    quantidade: { $sum: 1 },
    soma: { $sum: "$pedidos.total" },
    media: { $avg: "$pedidos.total" }
  } }
])
// Esperado: quantidade 3, soma 933,30 e média 311,10.

// C10. Pedidos do maior total para o menor, com desempate por número.
db.clientesPedidos.aggregate([
  { $unwind: "$pedidos" },
  { $project: { _id: 0, numero: "$pedidos.numero", total: "$pedidos.total" } },
  { $sort: { total: -1, numero: 1 } }
])
// Esperado: 155 (434,00), 101 (330,80), 113 (168,50).

// C11. Quantidade de pedidos por cidade de entrega.
db.clientesPedidos.aggregate([
  { $unwind: "$pedidos" },
  { $group: { _id: "$pedidos.endereco_entrega.cidade", total: { $sum: 1 } } },
  { $sort: { _id: 1 } }
])
// Esperado: Campinas 2; São Carlos 1.

// C12. O tipo de telefones varia entre documentos.
db.clientesPedidos.find(
  { telefones: { $type: "array" } },
  { _id: 1, nome: 1 }
).sort({ _id: 1 })
// Esperado: clientes 3, 4 e 5.
```

Os totais importados são números decimais comuns no JSON; a exibição pode ter pequenas diferenças de ponto flutuante. Para valores monetários em uma aplicação real, modele o tipo e as regras de arredondamento de forma explícita.
