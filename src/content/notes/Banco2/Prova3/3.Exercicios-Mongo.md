# 3.Exercicios-Mongo

## Antes de começar: importar clientes e pedidos no MongoDB em Docker

Os arquivos `clientes.json` e `pedidos_array.json` representam o modelo com **duas coleções separadas**: `clientes` tem oito documentos, e `pedidos` tem 13 documentos que se relacionam pelo campo `id_cliente`. O primeiro arquivo contém objetos JSON consecutivos; o segundo já é um array JSON. Por isso, só `clientes.json` precisa ser envolvido em um array com `jq -s`.

No terminal do computador que executa o Docker:

```bash
# Descubra o nome do contêiner MongoDB em execução.
docker ps --format 'table {{.Names}}\t{{.Image}}\t{{.Ports}}'

# Substitua meu-mongo pelo nome encontrado. jq roda no computador;
# mongoimport roda dentro do contêiner.
MONGO_CONTAINER=meu-mongo
cd ~/Downloads

jq -s '.' clientes.json |
  docker exec -i "$MONGO_CONTAINER" mongoimport \
    --db banco2_exercicios --collection clientes --jsonArray --stopOnError

docker exec -i "$MONGO_CONTAINER" mongoimport \
  --db banco2_exercicios --collection pedidos --jsonArray --stopOnError \
  < pedidos_array.json

# Abra o shell no mesmo banco usado na importação.
docker exec -it "$MONGO_CONTAINER" mongosh banco2_exercicios
```

No prompt do `mongosh`, confirme o resultado:

```javascript
db.clientes.countDocuments({}) // esperado: 8
db.pedidos.countDocuments({})  // esperado: 13
db.clientes.findOne({ _id: 8 })
db.pedidos.findOne({ _id: 101 })
```

O comando usa uma base de estudo própria e pressupõe conexão local **sem autenticação**. Se sua instância exige usuário, informe as credenciais e o banco de autenticação configurados no contêiner. Se `mongoimport` não existir nele, instale as **MongoDB Database Tools** no computador e conecte-se pela porta publicada do Docker; `mongosh` é distribuído separadamente como **MongoDB Shell**. Repetir o import na mesma coleção causa erro de `_id` duplicado. Consulte a documentação de [`mongoimport`](https://www.mongodb.com/docs/database-tools/mongoimport/mongoimport-guide/) e [`docker exec`](https://docs.docker.com/reference/cli/docker/container/exec/) para adaptar os comandos ao seu ambiente.

> Os exercícios **B1 e B2** dos slides pedem o pedido `_id: 15`, mas `pedidos_array.json` contém os IDs `101`, `155`, `113` e `201` a `210`. Para praticar exatamente o enunciado, você pode adicionar **um pedido fictício de treino** depois da importação:

#### Consulta rápida: qual operação escolher?

| Objetivo | Operação ou operador |
| --- | --- |
| Alterar um documento | `updateOne(filtro, alteracao)` |
| Alterar todos os documentos do filtro | `updateMany(filtro, alteracao)` |
| Criar ou substituir um campo | `$set` |
| Alterar campo aninhado sem substituir o objeto inteiro | `$set` com notação de ponto |
| Somar ou subtrair um número | `$inc` com valor positivo ou negativo |
| Remover um campo | `$unset` |
| Acrescentar ao array, permitindo repetição | `$push` |
| Acrescentar vários elementos separadamente | `$push` com `$each` |
| Acrescentar um valor somente se ainda não estiver no array | `$addToSet` |
| Remover do array por valor ou condição | `$pull` |
| Remover o primeiro ou o último elemento | `$pop: -1` ou `$pop: 1` |
| Alterar o primeiro item correspondente | `"itens.$.campo"`, com o item no filtro |
| Alterar todos os itens | `"itens.$[].campo"` |
| Alterar os itens que atendem a um filtro | `"itens.$[item].campo"` com `arrayFilters` |
| Criar quando não houver documento correspondente | `{ upsert: true }` no terceiro argumento |

> [!important] Documento, campo e elemento de array são coisas diferentes
> `deleteOne()` apaga o pedido inteiro. `$unset` apaga um campo. `$pull` remove elementos de um array e mantém o pedido. **`$push` adiciona, não remove.** Aqui, `$push` e `$addToSet` são operadores de atualização; em `aggregate()`, esses nomes também aparecem como acumuladores, sem gravar a alteração na coleção por si sós.

```javascript

db.bandas.find({}, { _id: 1 })

db.bandas.find(

db.bandas.aggregate([
  { $unwind: "$integrantes" },
```

## C. Gabarito dos exercícios criados para estudo

### C1 a C4 — conceitos

**C1.** (a) **Chave-valor** para recuperar um valor por sua chave; (b) **documentos** para reunir dados de cliente com estrutura variável; (c) **grafos** quando percorrer relações entre pessoas é central. São escolhas ligadas ao padrão de acesso, não apenas ao formato aparente dos dados.

**C2.** Uma **coleção separada de pedidos** tende a ser melhor nesse cenário. Cada pedido pode ser consultado e atualizado sem reescrever um documento de cliente que cresce continuamente. Incorporar pode ser útil quando os pedidos são poucos e quase sempre lidos com o cliente, mas não é a hipótese do enunciado.

**C3.** **Fragmentação** distribui partes diferentes dos dados por nós para dividir armazenamento e carga. **Replicação** mantém cópias dos mesmos dados em nós distintos, ajudando disponibilidade e, conforme a configuração, leitura. As duas estratégias podem ser combinadas.

**C4.** `{"ISODate": "..."}` é um objeto JSON com chave `ISODate`, não o marcador padrão de data no Extended JSON. O outro arquivo usa `{"$date": "2023-05-20T00:00:00Z"}`, que permite importar essa informação como data BSON. O passo com `jq -s` apenas envolve os oito documentos em um array; não altera o marcador `$date`.

### C17 a C20 — atualizar campos e conferir o resultado

Execute a carga de `pedidosAtualizacaoTreino` apresentada nos enunciados antes deste bloco. Os exercícios seguintes continuam alterando os mesmos documentos; os resultados pressupõem execução em ordem, sem repetir atualizações além do que foi pedido.

```javascript
// C17. Modifica dois campos e preserva entrega.uf.
db.pedidosAtualizacaoTreino.updateOne(
  { _id: 1001 },
  { $set: { status: "Pago", "entrega.cidade": "Campinas" } }
)
db.pedidosAtualizacaoTreino.findOne(
  { _id: 1001 }, { status: 1, entrega: 1 }
)
// Esperado: status Pago; entrega { cidade: "Campinas", uf: "SP" }.

// C18. Acrescenta frete e ajusta o total no mesmo documento.
db.pedidosAtualizacaoTreino.updateOne(
  { _id: 1001 },
  { $inc: { frete: 20, total: 20 } }
)
// Registra o desconto e diminui o total.
db.pedidosAtualizacaoTreino.updateOne(
  { _id: 1001 },
  { $inc: { desconto: 10, total: -10 } }
)
db.pedidosAtualizacaoTreino.findOne(
  { _id: 1001 }, { total: 1, frete: 1, desconto: 1 }
)
// Esperado: total 130, frete 20 e desconto 10.

// C19. Remove o campo, sem excluir o pedido.
db.pedidosAtualizacaoTreino.updateOne(
  { _id: 1001 },
  { $unset: { observacao: "" } }
)
db.pedidosAtualizacaoTreino.countDocuments({
  _id: 1001, observacao: { $exists: true }
})
// Esperado: 0. O campo não existe mais.
db.pedidosAtualizacaoTreino.findOne({ _id: 1001 })
// Esperado: o pedido continua existindo, sem observacao.

// C20. O filtro exige o cliente e o status indicados.
db.pedidosAtualizacaoTreino.updateMany(
  { id_cliente: 8, status: "Pendente" },
  { $set: { status: "Processando" } }
)
// Esperado: matchedCount 2 e modifiedCount 2.
db.pedidosAtualizacaoTreino.find(
  {}, { status: 1 }
).sort({ _id: 1 })
// Esperado: 1001 Pago; 1002 e 1003 Processando.
```

**Por que a notação de ponto em C17?** `$set: { entrega: { cidade: "Campinas" } }` substituiria o objeto `entrega` inteiro e removeria `uf`. Já `"entrega.cidade"` altera apenas a cidade. Definir `observacao: null` também não equivale a `$unset`: com `null`, o campo ainda existe.

O retorno da atualização ajuda a conferir o comando:

| Campo retornado | Significado |
| --- | --- |
| `matchedCount` | Quantos documentos corresponderam ao filtro |
| `modifiedCount` | Quantos documentos tiveram alguma alteração efetiva |
| `upsertedId` | ID do documento criado por upsert, quando houver inserção |

Se o documento já tiver o valor passado a `$set`, ele pode ser encontrado (`matchedCount: 1`) sem mudança (`modifiedCount: 0`). Esses contadores se referem a **documentos**, não à quantidade de campos ou de elementos de arrays alterados. `updateMany` não transforma o conjunto inteiro em uma transação atômica; cada documento é atualizado atomicamente.

### C21 a C25 — acrescentar e remover valores de arrays

```javascript
// C21. Executar duas vezes é parte deste exercício.
db.pedidosAtualizacaoTreino.updateOne(
  { _id: 1001 }, { $push: { tags: "urgente" } }
)
db.pedidosAtualizacaoTreino.updateOne(
  { _id: 1001 }, { $push: { tags: "urgente" } }
)
db.pedidosAtualizacaoTreino.findOne({ _id: 1001 }, { tags: 1 })
// Esperado: ["novo", "online", "urgente", "urgente"].

// C22. Cada string entra como um elemento separado.
db.pedidosAtualizacaoTreino.updateOne(
  { _id: 1001 },
  { $push: { tags: { $each: ["presente", "promocao"] } } }
)
db.pedidosAtualizacaoTreino.findOne({ _id: 1001 }, { tags: 1 })
// Esperado: ["novo", "online", "urgente", "urgente", "presente", "promocao"].

// C23. Só acrescenta valores ainda ausentes.
db.pedidosAtualizacaoTreino.updateOne(
  { _id: 1001 },
  { $addToSet: { tags: { $each: ["urgente", "vip"] } } }
)
db.pedidosAtualizacaoTreino.findOne({ _id: 1001 }, { tags: 1 })
// Esperado: acrescenta vip; ainda existem duas ocorrências de urgente.

// C24. Remove todas as ocorrências do valor, não apenas a primeira.
db.pedidosAtualizacaoTreino.updateOne(
  { _id: 1001 }, { $pull: { tags: "urgente" } }
)
// Esperado: matchedCount 1 e modifiedCount 1, embora remova dois elementos.
db.pedidosAtualizacaoTreino.findOne({ _id: 1001 }, { tags: 1 })
// Restam: novo, online, presente, promocao e vip.

// C25. Um dos valores da lista é suficiente para o elemento ser removido.
db.pedidosAtualizacaoTreino.updateOne(
  { _id: 1001 },
  { $pull: { tags: { $in: ["novo", "promocao"] } } }
)
db.pedidosAtualizacaoTreino.findOne({ _id: 1001 }, { tags: 1 })
// Restam: online, presente e vip.
```

**C21:** `$push` aceita valores repetidos. **C22:** sem `$each`, passar `tags: ["presente", "promocao"]` ao `$push` acrescentaria **um array dentro de `tags`**, em vez de duas strings independentes. **C23:** `$addToSet` impede novas inclusões de um valor já presente, mas **não limpa duplicatas antigas** nem garante uma ordem específica para os valores.

`$pull` examina os elementos do array do documento selecionado pelo filtro. Ele também aceita condições numéricas, como `$gte`, e condições sobre campos de documentos incorporados, como em C31. Já `deleteMany({ tags: "urgente" })` apagaria **pedidos inteiros** que tivessem essa tag.

### C26 e C27 — posição e documentos incorporados

```javascript
// C26. Retira do início: criado.
db.pedidosAtualizacaoTreino.updateOne(
  { _id: 1001 }, { $pop: { historico: -1 } }
)
db.pedidosAtualizacaoTreino.findOne({ _id: 1001 }, { historico: 1 })
// Esperado: ["validado", "separado"].

// Retira do fim: separado.
db.pedidosAtualizacaoTreino.updateOne(
  { _id: 1001 }, { $pop: { historico: 1 } }
)
db.pedidosAtualizacaoTreino.findOne({ _id: 1001 }, { historico: 1 })
// Esperado: ["validado"].

// C27. Acrescenta um documento como elemento do array itens.
db.pedidosAtualizacaoTreino.updateOne(
  { _id: 1001 },
  { $push: { itens: { codigo: 104, descricao: "Borracha", qtde: 2, preco: 5 } } }
)
db.pedidosAtualizacaoTreino.findOne({ _id: 1001 }, { itens: 1, total: 1 })
// Esperado: três itens, com códigos 101, 102 e 104. total continua 130.
```

`$pop` usa a **posição**: `-1` é o início e `1` é o fim. Ele não procura um valor específico, ao contrário de `$pull`. As alterações anteriores de `status` não acrescentaram registros ao `historico`; isso exigiria uma atualização explícita.

> [!note] Itens não recalculam o total automaticamente
> `total` é um campo armazenado, não uma fórmula. C27 a C31 alteram itens sem ajustar esse campo para isolar o efeito de cada operador. Em **C33**, o total é recalculado com os itens restantes, frete e desconto. Em uma aplicação, essa consistência deve fazer parte da operação de atualização.

### C28 a C31 — alterar e remover itens específicos

```javascript
// C28. O filtro identifica o pedido E o item.
db.pedidosAtualizacaoTreino.updateOne(
  { _id: 1001, "itens.codigo": 102 },
  { $set: { "itens.$.qtde": 5 } }
)
db.pedidosAtualizacaoTreino.findOne({ _id: 1001 }, { itens: 1 })
// Esperado: só a quantidade da Caneta muda, de 4 para 5.

// C29. arrayFilters escolhe os elementos dentro do pedido encontrado.
db.pedidosAtualizacaoTreino.updateOne(
  { _id: 1001 },
  { $set: { "itens.$[item].promocional": true } },
  { arrayFilters: [{ "item.preco": { $gte: 10 } }] }
)
// Esperado: matchedCount 1 e modifiedCount 1.
db.pedidosAtualizacaoTreino.findOne({ _id: 1001 }, { itens: 1 })
// Os itens 101 e 102 recebem promocional: true. O item 104 não recebe o campo.

// C30. Todos os elementos de itens, dentro do pedido 1001.
db.pedidosAtualizacaoTreino.updateOne(
  { _id: 1001 },
  { $set: { "itens.$[].conferido": true } }
)
db.pedidosAtualizacaoTreino.findOne({ _id: 1001 }, { itens: 1 })
// Esperado: os três itens têm conferido: true.

// C31. O critério se aplica a cada documento dentro de itens.
db.pedidosAtualizacaoTreino.updateOne(
  { _id: 1001 },
  { $pull: { itens: { qtde: { $lte: 2 } } } }
)
db.pedidosAtualizacaoTreino.findOne({ _id: 1001 }, { itens: 1 })
// Esperado: apenas a Caneta, codigo 102, qtde 5 e preco 10.
// Ela mantém promocional: true e conferido: true. O pedido continua existindo.
```

| Caminho de atualização | Quais elementos altera? |
| --- | --- |
| `"itens.0.qtde"` | O elemento de índice 0, independentemente do código |
| `"itens.$.qtde"` | O primeiro elemento correspondente ao filtro da consulta |
| `"itens.$[].conferido"` | Todos os elementos do array no documento selecionado |
| `"itens.$[item].promocional"` | Os elementos que atendem ao filtro `item` em `arrayFilters` |

**`updateMany` escolhe quantos documentos atualizar; os operadores posicionais escolhem quais elementos de array atualizar dentro deles.** Usar `updateMany` com `$` não faz `$` significar todos os elementos.

Em C28, o código do item é único no array de treino. Se houvesse códigos repetidos, `$` alteraria somente o primeiro correspondente; para atingir todos os correspondentes, use `$[item]` com `arrayFilters`. Em C31, `$pull` remove **Livro e Borracha**, pois ambos têm quantidade 2, mas `modifiedCount` continua sendo 1: um pedido foi modificado.

`$unset` aplicado diretamente a uma posição do array, como `"itens.0"`, deixa `null` nessa posição; não reorganiza o array removendo o elemento. Para retirar um item pelo critério, use `$pull`. Para remover apenas um campo interno, como `"itens.$.promocional"`, `$unset` remove o campo daquele item, preservando o documento do item.

### C32 — documento inexistente, criação e repetição

```javascript
// Sem upsert: encontrar zero documentos não insere nada.

  { $set: { status: "Pendente" } }

// Esperado: matchedCount 0 e modifiedCount 0.
db.pedidosAtualizacaoTreino.findOne({ _id: 1004 })
// Esperado: null.

// Com upsert: cria se não existir; campos iniciais só entram na inserção.
db.pedidosAtualizacaoTreino.updateOne(
  { _id: 1004 },
  {
    $set: { status: "Pendente" },
    $setOnInsert: { id_cliente: 3, total: 0, itens: [], tags: [] }
  },
  { upsert: true }
)
// Primeira execução: matchedCount 0, modifiedCount 0 e upsertedId 1004.

db.pedidosAtualizacaoTreino.updateOne(
  { _id: 1004 },
  {
    $set: { status: "Pendente" },
    $setOnInsert: { id_cliente: 3, total: 0, itens: [], tags: [] }
  },
  { upsert: true }
)
// Segunda execução: matchedCount 1, modifiedCount 0 e upsertedId null.

db.pedidosAtualizacaoTreino.findOne({ _id: 1004 })
// Esperado: { _id: 1004, status: "Pendente", id_cliente: 3,
//             total: 0, itens: [], tags: [] }, sem depender da ordem dos campos.
```

`upsert: true` é uma **opção**, no terceiro argumento. `$setOnInsert` é um **operador** de atualização: define campos apenas quando esse upsert resulta em inserção. Na segunda execução, não recria nem zera os arrays; `$set` também não altera o status porque ele já é `Pendente`.

### C33 — complementar: atualização com pipeline

Em vez do objeto tradicional de operadores, o segundo argumento pode ser um **array de etapas de agregação permitidas na atualização**. Assim, o cálculo usa os campos do próprio documento:

```javascript
db.pedidosAtualizacaoTreino.updateOne(
  { _id: 1001 },
  [
    { $set: {
      total: {
        $subtract: [
          { $add: [
            { $sum: {
              $map: {
                input: "$itens",
                as: "item",
                in: { $multiply: ["$$item.qtde", "$$item.preco"] }
              }
            } },
            "$frete"
          ] },
          "$desconto"
        ]
      }
    } }
  ]
)

db.pedidosAtualizacaoTreino.findOne(
  { _id: 1001 }, { itens: 1, frete: 1, desconto: 1, total: 1 }
)
// Esperado: total 60, pois 5 × 10 + 20 − 10 = 60.
```

`$map` produz o subtotal de cada item; `$sum` soma esses subtotais; `$add` inclui o frete e `$subtract` retira o desconto. O uso de `$sum` aqui é uma **expressão sobre o array**, não um agrupamento de pedidos com `$group`.

O pipeline acima pressupõe os campos numéricos e arrays da carga de treino. Não copie o cálculo para documentos com campos ausentes ou tipos diferentes sem adaptar a regra. A operação persiste o novo total; uma consulta `aggregate()` comum apenas calcula e retorna o resultado.
