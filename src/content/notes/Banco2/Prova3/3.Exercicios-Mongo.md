# 3.Exercicios-Mongo

## Antes de começar: importar clientes e pedidos no MongoDB em Docker

Os arquivos `clientes.json` e `pedidos_array.json` representam o modelo com **duas coleções separadas**: `clientes` tem oito documentos, e `pedidos` tem 13 documentos que se relacionam pelo campo `id_cliente`. O primeiro arquivo contém objetos JSON consecutivos; o segundo já é um array JSON. Por isso, só `clientes.json` precisa ser envolvido em um array com `jq -s`.

No terminal do computador que executa o Docker:

```bash
# Descubra o nome do contêiner MongoDB em execução.
docker ps --format 'table {{.Names}}\t{{.Image}}\t{{.Ports}}'

# Substitua meu-mongo pelo nome encontrado. jq roda no computador;
# mongoimport roda dentro do contêiner.
MONGO_CONTAINER=meu-mongo
cd ~/Downloads

jq -s '.' clientes.json |
  docker exec -i "$MONGO_CONTAINER" mongoimport \
    --db banco2_exercicios --collection clientes --jsonArray --stopOnError

docker exec -i "$MONGO_CONTAINER" mongoimport \
  --db banco2_exercicios --collection pedidos --jsonArray --stopOnError \
  < pedidos_array.json

# Abra o shell no mesmo banco usado na importação.
docker exec -it "$MONGO_CONTAINER" mongosh banco2_exercicios
```

No prompt do `mongosh`, confirme o resultado:

```javascript
db.clientes.countDocuments({}) // esperado: 8
db.pedidos.countDocuments({})  // esperado: 13
db.clientes.findOne({ _id: 8 })
db.pedidos.findOne({ _id: 101 })
```

O comando usa uma base de estudo própria e pressupõe conexão local **sem autenticação**. Se sua instância exige usuário, informe as credenciais e o banco de autenticação configurados no contêiner. Se `mongoimport` não existir nele, instale as **MongoDB Database Tools** no computador e conecte-se pela porta publicada do Docker; `mongosh` é distribuído separadamente como **MongoDB Shell**. Repetir o import na mesma coleção causa erro de `_id` duplicado. Consulte a documentação de [`mongoimport`](https://www.mongodb.com/docs/database-tools/mongoimport/mongoimport-guide/) e [`docker exec`](https://docs.docker.com/reference/cli/docker/container/exec/) para adaptar os comandos ao seu ambiente.

> [!important] O pedido 15 não está no arquivo
> Os exercícios **B1 e B2** dos slides pedem o pedido `_id: 15`, mas `pedidos_array.json` contém os IDs `101`, `155`, `113` e `201` a `210`. Para praticar exatamente o enunciado, você pode adicionar **um pedido fictício de treino** depois da importação:
>
> ```javascript
> db.pedidos.insertOne({
>   _id: 15,
>   id_cliente: 8,
>   data: ISODate("2024-11-05"),
>   status: "Aberto",
>   total: 0,
>   itens: []
> })
> ```
>
> Depois disso, `db.pedidos.countDocuments({})` passa a retornar **14**. Esse registro foi criado para estudo; não faz parte do JSON nem do exemplo original dos slides.

### Opcional: dados com pedidos incorporados para o bloco C

Os exercícios autorais **C5 a C12** usam **outro modelo**, no qual cada cliente possui um array `pedidos`. Para executá-los, importe também `clientes_pedidos.json` em uma **terceira coleção**, sem misturá-lo com `clientes` e `pedidos`:

```bash
jq -s '.' clientes_pedidos.json |
  docker exec -i "$MONGO_CONTAINER" mongoimport \
    --db banco2_exercicios --collection clientesPedidos --jsonArray --stopOnError
```

Esse arquivo tem oito objetos JSON consecutivos e representa datas com `{"$date": "..."}`. Já `clientes_pedidos_array.json` usa `{"ISODate": "..."}` em algumas datas, que **não** é o marcador de data BSON do [Extended JSON](https://www.mongodb.com/docs/manual/reference/mongodb-extended-json/). Além disso, no cliente `_id: 3`, o pedido `155` tem `total: 434.0` no arquivo escolhido para importação e `330.8` no arquivo em array. O gabarito C considera **434,00**; os itens desse pedido somam 387,50 + 3 × 15,50 = **434,00**.

> [!important] Qual coleção usar?
> **A** usa `bandas`, `locais` e `shows`, criadas pelo mini script a seguir. **B** usa `clientes` e `pedidos` separados, importados dos novos arquivos. **C5 a C12** usam `clientesPedidos`, importada apenas no passo opcional. Escolha a coleção correspondente antes de executar a solução.

## Mini script para os exercícios de bandas, locais e shows

O guia apresenta a estrutura de exemplo, mas não fornece um conjunto completo de documentos para importar. O script abaixo é **criado para estudo**, seguindo os campos do guia. Cole-o no `mongosh` já conectado a `banco2_exercicios`. Execute **uma vez**: os `_id` são fixos, e uma segunda inserção causará erro de chave duplicada.

```javascript
var bandasBase = [
  { _id: "Coldplay", ano_criacao: 1996, integrantes: [
    { nome: "Chris Martin", instrumentos: ["Vocal", "Piano"] },
    { nome: "Jonny Buckland", instrumentos: ["Guitarra"] }
  ] },
  { _id: "U2", ano_criacao: 1976, integrantes: [
    { nome: "Bono", instrumentos: ["Vocal"] },
    { nome: "The Edge", instrumentos: ["Guitarra"] }
  ] },
  { _id: "Rolling Stones", ano_criacao: 1962, integrantes: [
    { nome: "Mick Jagger", instrumentos: ["Vocal", "Gaita"] },
    { nome: "Keith Richards", instrumentos: ["Guitarra"] }
  ] },
  { _id: "Iron Maiden", ano_criacao: 1975, integrantes: [
    { nome: "Bruce Dickinson", instrumentos: ["Vocal"] },
    { nome: "Steve Harris", instrumentos: ["Baixo"] }
  ] }
]

var locaisBase = [
  { _id: "Maracanã", cidade: "Rio de Janeiro", estado: "RJ",
    valor_aluguel: 500000, capacidade_publico: 78838, disponivel: false },
  { _id: "Allianz Parque", cidade: "São Paulo", estado: "SP",
    valor_aluguel: 350000, capacidade_publico: 55000, disponivel: false },
  { _id: "Morumbi", cidade: "São Paulo", estado: "SP",
    valor_aluguel: 300000, capacidade_publico: 60000, disponivel: true },
  { _id: "Espaço Central", cidade: "São Paulo", estado: "SP",
    valor_aluguel: 30000, capacidade_publico: 5000, disponivel: true }
]

db.bandas.insertMany(bandasBase)
db.locais.insertMany(locaisBase)

var agendaBase = [
  { banda: "Coldplay", local: "Maracanã", data: "2024-12-15",
    valor_ingresso: 350, total_ingressos: 70000, ingressos_vendidos: 60000 },
  { banda: "Coldplay", local: "Allianz Parque", data: "2024-12-07",
    valor_ingresso: 450, total_ingressos: 50000, ingressos_vendidos: 42000 },
  { banda: "U2", local: "Morumbi", data: "2024-06-20",
    valor_ingresso: 550, total_ingressos: 58000, ingressos_vendidos: 54000 },
  { banda: "Rolling Stones", local: "Morumbi", data: "2023-11-30",
    valor_ingresso: 600, total_ingressos: 57000, ingressos_vendidos: 50000 },
  { banda: "Iron Maiden", local: "Allianz Parque", data: "2024-10-19",
    valor_ingresso: 400, total_ingressos: 48000, ingressos_vendidos: 30000 }
]

db.shows.insertMany(agendaBase.map(show => {
  var banda = bandasBase.find(b => b._id === show.banda)
  var local = locaisBase.find(l => l._id === show.local)
  return {
    _id: { banda: show.banda, local: show.local, data: show.data },
    valor_ingresso: show.valor_ingresso,
    total_ingressos: show.total_ingressos,
    ingressos_vendidos: show.ingressos_vendidos,
    detalhes_banda: {
      ano_criacao: banda.ano_criacao,
      integrantes: banda.integrantes
    },
    detalhes_local: {
      cidade: local.cidade,
      estado: local.estado,
      valor_aluguel: local.valor_aluguel,
      capacidade_publico: local.capacidade_publico
    }
  }
}))
```

```javascript
db.bandas.countDocuments({}) // 4
db.locais.countDocuments({}) // 4
db.shows.countDocuments({})  // 5
```

Em `bandas`, o nome é `_id`. Em `shows`, `_id` contém banda, local e data; a data é **string** no formato `AAAA-MM-DD`, como no guia. O script acrescenta `locais.disponivel` e `shows.ingressos_vendidos` **apenas para praticar** A7, A18 e A27; esses campos não aparecem no esquema original dos slides. Aqui `disponivel` significa uma marcação simples de cadastro, **não** disponibilidade para uma data específica.

# Resoluções

## A. Gabarito dos exercícios da aula: bandas, locais e shows

As respostas usam o modelo do guia e podem ser testadas com o **mini script** do início da nota. Esse conjunto de treino foi criado aqui; não é um banco de dados distribuído junto aos slides. `find()` retorna um cursor; `findOne()` retorna um documento ou `null`.

### A1 a A6 — consultas básicas, projeção e arrays

```javascript
// A1. Todas as bandas.
db.bandas.find({})

// A2. O nome da banda é o campo _id no modelo da aula.
db.bandas.find({}, { _id: 1 })

// A3. Uma banda específica.
db.bandas.findOne({ _id: "U2" })

// A4. Após 1990: 1990 não entra no resultado.
db.bandas.find(
  { ano_criacao: { $gt: 1990 } },
  { _id: 1, ano_criacao: 1 }
)

// A5. Desdobra os integrantes para selecionar exatamente Mick Jagger.
db.bandas.aggregate([
  { $unwind: "$integrantes" },
  { $match: { "integrantes.nome": "Mick Jagger" } },
  { $project: { _id: 0, banda: "$_id", instrumentos: "$integrantes.instrumentos" } }
])

// A6. Capacidade estritamente superior a 60.000.
db.locais.find({ capacidade_publico: { $gt: 60000 } })
```

### A7 a A13 — shows e locais

**A7.** O modelo original de `locais` **não possui disponibilidade** nem uma data para verificar a agenda. O mini script acrescentou `disponivel` como marcação simples de cadastro. Nesse conjunto de treino:

```javascript
db.locais.find({ cidade: "São Paulo", disponivel: true })
// Esperado: Morumbi e Espaço Central.
```

Isso não diz se o local está livre **em uma data específica**. Para responder a essa pergunta, seria preciso definir a data e comparar com a agenda de shows.

```javascript
// A8. Local e data dos shows do Coldplay.
db.shows.aggregate([
  { $match: { "_id.banda": "Coldplay" } },
  { $project: { _id: 0, local: "$_id.local", data: "$_id.data" } }
])

// A9. Banda e data dos shows no Allianz Parque.
db.shows.aggregate([
  { $match: { "_id.local": "Allianz Parque" } },
  { $project: { _id: 0, banda: "$_id.banda", data: "$_id.data" } }
])

// A10. A data foi armazenada como string AAAA-MM-DD no modelo da aula.
db.shows.find({ "_id.data": "2024-12-07" })

// A11. Exemplo de cidade específica: São Paulo.
db.shows.find({ "detalhes_local.cidade": "São Paulo" })

// A12. Abaixo de R$ 500; ingressos de R$ 500 não entram.
db.shows.find({ valor_ingresso: { $lt: 500 } })

// A13. Bandas distintas com show no Morumbi.
db.shows.distinct("_id.banda", { "_id.local": "Morumbi" })
```

Em **A8** e **A9**, `$project` cria nomes de saída (`local`, `data`, `banda`) a partir dos subcampos de `_id`. Se preferir uma consulta simples, use `find()` sem projeção e leia os subcampos no resultado.

### A14 a A20 — datas, contagem e extremos

```javascript
// A14. Intervalo de strings ISO: inclui todo o ano de 2024.
db.shows.find({ "_id.data": { $gte: "2024-01-01", $lt: "2025-01-01" } })

// A15. Mesmo intervalo, só para Coldplay.
db.shows.find({
  "_id.banda": "Coldplay",
  "_id.data": { $gte: "2024-01-01", $lt: "2025-01-01" }
})

// A16. Exemplo de local específico: Maracanã.
db.shows.countDocuments({ "_id.local": "Maracanã" })

// A17. Estado do local, copiado para o documento do show.
db.shows.find({ "detalhes_local.estado": "SP" })
```

**A18.** `total_ingressos` informa quantos ingressos foram oferecidos inicialmente. O mini script acrescentou `ingressos_vendidos`, permitindo calcular o restante:

```javascript
db.shows.aggregate([
  { $match: { "_id.banda": "Iron Maiden" } },
  { $project: {
    _id: 1,
    ingressosDisponiveis: { $subtract: ["$total_ingressos", "$ingressos_vendidos"] }
  } }
])
// Esperado no mini script: 18.000.
```

Sem o campo extra, só seria possível consultar a oferta inicial com `total_ingressos`; o esquema dos slides não informa quantos foram vendidos ou reservados.

```javascript
// A19. Menor ano de criação entre as bandas.
db.bandas.find({}, { _id: 0, ano_criacao: 1 })
  .sort({ ano_criacao: 1 }).limit(1)

// A20. Local de maior capacidade.
db.locais.find({}).sort({ capacidade_publico: -1 }).limit(1)
```

### A21 a A28 — agregações

```javascript
// A21. Capacidade média dos locais.
db.locais.aggregate([
  { $group: { _id: null, capacidadeMedia: { $avg: "$capacidade_publico" } } }
])

// A22. Total de ingressos colocados à disposição.
db.shows.aggregate([
  { $group: { _id: null, totalIngressos: { $sum: "$total_ingressos" } } }
])

// A23. Receita hipotética se todos os ingressos forem vendidos.
db.shows.aggregate([
  { $group: {
    _id: null,
    arrecadacao: { $sum: { $multiply: ["$valor_ingresso", "$total_ingressos"] } }
  } }
])

// A24. Quantos shows cada banda realizou.
db.shows.aggregate([
  { $group: { _id: "$_id.banda", totalShows: { $sum: 1 } } },
  { $sort: { _id: 1 } }
])

// A25. Quantos shows ocorreram em cada local.
db.shows.aggregate([
  { $group: { _id: "$_id.local", totalShows: { $sum: 1 } } },
  { $sort: { _id: 1 } }
])

// A26. Média simples do preço do ingresso por show.
db.shows.aggregate([
  { $group: { _id: null, precoMedio: { $avg: "$valor_ingresso" } } }
])
```

**A27.** Com `ingressos_vendidos` do mini script, calcule a diferença e ordene pelo maior restante:

```javascript
db.shows.aggregate([
  { $project: {
    restantes: { $subtract: ["$total_ingressos", "$ingressos_vendidos"] }
  } },
  { $sort: { restantes: -1 } },
  { $limit: 1 }
])
// Esperado no mini script: Iron Maiden no Allianz Parque, com 18.000.
```

Sem informação sobre vendas, a pergunta **não tem resposta exata** no modelo dos slides. Se “disponíveis” significar apenas *oferecidos inicialmente*, use `db.shows.find({}).sort({ total_ingressos: -1 }).limit(1)`; isso responde a outra interpretação.

```javascript
// A28. Aluguel médio dos locais.
db.locais.aggregate([
  { $group: { _id: null, aluguelMedio: { $avg: "$valor_aluguel" } } }
])
```

> [!note] Limites dos dados
> **A7, A18 e A27** exigem uma definição de disponibilidade ou dados extras que não estão no esquema original. O mini script acrescenta esses dados e declara o significado usado. **A23** é uma simulação expressamente pedida no enunciado. **A26** dá o mesmo peso a cada show; não é o preço médio ponderado pelo número de ingressos.

## B. Gabarito dos exercícios da aula: clientes e pedidos separados

Execute estes comandos nas coleções separadas `clientes` e `pedidos` importadas no início. O cliente `_id: 8` está em `clientes.json`.
```javascript
// B1. Todos os dados do pedido 15.
db.pedidos.findOne({ _id: 15 })

// B2. Um único update para as duas alterações solicitadas.
db.pedidos.updateOne(
  { _id: 15 },
  { $set: { data_cancelamento: ISODate("2024-11-05"), status: "Cancelado" } }
)

// B3. O campo "e-mail" segue o nome usado nos slides.
db.clientes.updateOne(
  { _id: 8 },
  { $set: { "e-mail": "cliente8@example.com" } }
)

// B4. Notação de ponto: adiciona Casa sem substituir os demais telefones.
db.clientes.updateOne(
  { _id: 8 },
  { $set: { "telefones.Casa": { ddd: 16, numero: "3422-9876" } } }
)

// B5. Adiciona um endereço de trabalho.
db.clientes.updateOne(
  { _id: 8 },
  { $set: { "enderecos.trabalho": {
    rua: "R. José Manoel, 54",
    bairro: "Vila Sesamo",
    cidade: "Ribeirão Preto"
  } } }
)

// B6. Altera apenas a validade de metodo1.
db.clientes.updateOne(
  { _id: 8 },
  { $set: { "metodos.metodo1.validade": "12/25" } }
)
```

Se `matchedCount` for `0`, confira o banco e a coleção. Para **B2**, verifique especialmente se você adicionou o pedido de treino `_id: 15`. O uso de `updateOne()` mantém o filtro por `_id` explícito e evita modificar outro documento.

## C. Gabarito dos exercícios criados para estudo

### C1 a C4 — conceitos

**C1.** (a) **Chave-valor** para recuperar um valor por sua chave; (b) **documentos** para reunir dados de cliente com estrutura variável; (c) **grafos** quando percorrer relações entre pessoas é central. São escolhas ligadas ao padrão de acesso, não apenas ao formato aparente dos dados.

**C2.** Uma **coleção separada de pedidos** tende a ser melhor nesse cenário. Cada pedido pode ser consultado e atualizado sem reescrever um documento de cliente que cresce continuamente. Incorporar pode ser útil quando os pedidos são poucos e quase sempre lidos com o cliente, mas não é a hipótese do enunciado.

**C3.** **Fragmentação** distribui partes diferentes dos dados por nós para dividir armazenamento e carga. **Replicação** mantém cópias dos mesmos dados em nós distintos, ajudando disponibilidade e, conforme a configuração, leitura. As duas estratégias podem ser combinadas.

**C4.** `{"ISODate": "..."}` é um objeto JSON com chave `ISODate`, não o marcador padrão de data no Extended JSON. O outro arquivo usa `{"$date": "2023-05-20T00:00:00Z"}`, que permite importar essa informação como data BSON. O passo com `jq -s` apenas envolve os oito documentos em um array; não altera o marcador `$date`.

### C5 a C12 — dados de `clientesPedidos`

```javascript
// C5. Quantidade de clientes.
db.clientesPedidos.countDocuments({})
// Esperado nos dados fornecidos: 8.

// C6. Array de pedidos vazio.
db.clientesPedidos.find(
  { pedidos: { $size: 0 } },
  { _id: 1, nome: 1 }
).sort({ _id: 1 })
// Esperado: _id 2, 4, 5, 6 e 8.

// C7. Uma linha por pedido incorporado.
db.clientesPedidos.aggregate([
  { $unwind: "$pedidos" },
  { $project: {
    _id: 0,
    idCliente: "$_id",
    numero: "$pedidos.numero",
    total: "$pedidos.total"
  } },
  { $sort: { idCliente: 1 } }
])
// Esperado: pedidos 101, 155 e 113, dos clientes 1, 3 e 7.

// C8. Pelo menos um pedido com entrega em Campinas.
db.clientesPedidos.find(
  { "pedidos.endereco_entrega.cidade": "Campinas" },
  { _id: 1, nome: 1 }
).sort({ _id: 1 })
// Esperado: clientes 1 e 7.

// C9. Estatísticas dos totais dos pedidos.
db.clientesPedidos.aggregate([
  { $unwind: "$pedidos" },
  { $group: {
    _id: null,
    quantidade: { $sum: 1 },
    soma: { $sum: "$pedidos.total" },
    media: { $avg: "$pedidos.total" }
  } }
])
// Esperado: quantidade 3, soma 933,30 e média 311,10.

// C10. Pedidos do maior total para o menor, com desempate por número.
db.clientesPedidos.aggregate([
  { $unwind: "$pedidos" },
  { $project: { _id: 0, numero: "$pedidos.numero", total: "$pedidos.total" } },
  { $sort: { total: -1, numero: 1 } }
])
// Esperado: 155 (434,00), 101 (330,80), 113 (168,50).

// C11. Quantidade de pedidos por cidade de entrega.
db.clientesPedidos.aggregate([
  { $unwind: "$pedidos" },
  { $group: { _id: "$pedidos.endereco_entrega.cidade", total: { $sum: 1 } } },
  { $sort: { _id: 1 } }
])
// Esperado: Campinas 2; São Carlos 1.

// C12. O tipo de telefones varia entre documentos.
db.clientesPedidos.find(
  { telefones: { $type: "array" } },
  { _id: 1, nome: 1 }
).sort({ _id: 1 })
// Esperado: clientes 3, 4 e 5.
```

Os totais importados são números decimais comuns no JSON; a exibição pode ter pequenas diferenças de ponto flutuante. Para valores monetários em uma aplicação real, modele o tipo e as regras de arredondamento de forma explícita.
